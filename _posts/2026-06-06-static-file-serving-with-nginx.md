# 정적 파일 서빙(static file serving)이란

React를 배포하면 nginx라는 게 화면을 보여준다고 하는데, nginx가 정확히 뭘 하는 건지 헷갈렸음. 알고 보니 그냥 "디스크에 있는 파일을 꺼내서 보내주는 일"이었음


## 1. 정적 파일이 뭔가

정적(static) 파일은 **미리 다 만들어져서 그대로 보내주기만 하면 되는 파일**임.

- HTML 파일
- CSS 파일
- JavaScript 파일
- 이미지(png, jpg)

이런 건 사용자마다 내용이 바뀌지 않음. 누가 요청하든 똑같은 파일을 그대로 주면 됨. 그래서 "정적"이라고 부름.

반대로 "동적"인 건, 요청할 때마다 DB 뒤져서 매번 다른 결과를 만들어주는 거임(스프링이 하는 일).


## 2. nginx가 하는 일

nginx는 정적 파일을 잘 꺼내주는 도구임. 동작은 단순함.

```
사용자: "index.html 줘"
nginx:  디스크에서 index.html 찾음 → 그대로 보내줌
```

DB도 안 보고, 계산도 안 하고, 그냥 **디스크에 있는 파일을 찾아서 그대로 전달**함. 그래서 엄청 빠름.

도서관 사서가 책 번호 들으면 서가에서 그 책을 꺼내다 주는 느낌임. 책 내용을 새로 쓰는 게 아니라 이미 있는 걸 꺼내주기만 함.


## 3. React랑 무슨 상관인가

React 프로젝트를 빌드하면 결국 HTML/CSS/JS 파일 덩어리가 나옴(보통 `dist` 폴더). 이게 다 정적 파일임.

그래서 배포할 때 이 파일들을 nginx한테 맡김.

```
[사용자 브라우저]
   → "사이트 접속" 요청
   → nginx가 빌드된 index.html, JS, CSS를 꺼내서 보내줌
   → 브라우저가 그걸 받아서 React 화면을 띄움
```

데이터(JSON)는 백엔드가 주고, 화면 파일(HTML/JS/CSS)은 nginx가 주는 구조임.


## 4. 정리

- 정적 파일 = 미리 만들어져 그대로 보내면 되는 파일(HTML/CSS/JS/이미지).
- nginx = 디스크에서 그 파일을 찾아 그대로 보내주는 도구.
- React 빌드 결과물(`dist`)을 nginx가 서빙해서 사용자한테 화면을 띄워줌.

> 정적 파일 서빙은 "계산 없이 파일을 꺼내 전달"하는 단순한 일이라, 그래서 빠르고 nginx가 잘함.
