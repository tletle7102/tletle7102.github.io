# 점진적 마이그레이션 (Incremental Migration)

Thymeleaf로 만든 걸 React로 바꾸려면 다 갈아엎어야 하는 줄 알았음. 근데 그렇게 하면 위험해서, 조금씩 옮기는 방법(점진적 마이그레이션)을 쓴다고 해서 정리함


## 1. 한 번에 다 바꾸면 왜 위험한가

기존에 잘 돌아가던 Thymeleaf 프로젝트를 통째로 React로 갈아엎으면:

- 다 만들 때까지 서비스를 못 내보냄(몇 달 멈춤).
- 한 번에 바꾸니 문제가 터지면 어디가 원인인지 찾기 힘듦.
- 옛날 기능 중 빠뜨린 게 배포 후에 발견됨.

위험이 큼. 그래서 "한 번에"가 아니라 "조금씩" 옮김.


## 2. 점진적 마이그레이션이란

**기존 걸 돌리면서, 화면을 하나씩 React로 바꿔가는 방식**임. 옛날(Thymeleaf)과 새것(React)이 한동안 공존함.

```
처음:   [Thymeleaf 화면 전부]
1단계:  [React 화면 1개] + [Thymeleaf 나머지]
2단계:  [React 화면 3개] + [Thymeleaf 나머지]
...
마지막: [React 화면 전부]   ← Thymeleaf 제거
```

집 인테리어를 방 하나씩 고치는 느낌임. 사는 동안 한 방씩 바꾸지, 집 전체를 한 번에 부수고 새로 짓진 않음.


## 3. 어떻게 공존시키나

보통 이렇게 함.

- 백엔드를 먼저 JSON 주는 API로 정리해둠(화면과 데이터 분리).
- 새로 만드는 화면은 React로 만들어 그 API를 호출.
- 아직 안 옮긴 화면은 기존 Thymeleaf가 계속 담당.
- 라우팅(Traefik/nginx 등)에서 "이 경로는 React로, 저 경로는 기존으로" 나눠 보냄.

이러면 서비스는 계속 돌아가면서, 화면만 하나씩 React로 갈아끼울 수 있음.


## 4. 그래서 좋은 점

- **서비스 안 멈춤**: 옮기는 중에도 사용자는 계속 씀.
- **위험 작음**: 한 화면씩 바꾸니 문제 나도 그 화면만 보면 됨.
- **되돌리기 쉬움**: 새 화면이 문제면 그것만 잠깐 기존으로 되돌림.


## 5. 정리

- 한 번에 갈아엎기는 위험함(오래 멈추고 원인 찾기 힘듦).
- 점진적 마이그레이션은 기존을 돌리면서 화면을 하나씩 React로 옮김.
- 백엔드를 API로 분리해두는 게 그 출발점.
