# SPA 마이그레이션 시 자주 만나는 함정 7가지

Thymeleaf에서 React(SPA)로 옮기면서 "이건 왜 이러지?" 했던 것들을 모아 정리함. 대부분 SPA의 동작 방식을 몰라서 겪는 함정이었음

> SPA(Single Page Application) = 페이지를 새로 안 받고, 자바스크립트로 화면만 바꿔치기하는 방식. React가 이 방식임.


## 함정 1. 새로고침하면 404

SPA는 주소가 `/users/1`이어도 실제 서버엔 그런 파일이 없음. JS가 화면을 그릴 뿐임. 그래서 그 주소에서 새로고침하면 서버가 "그런 파일 없는데?" 하고 404를 줌.

- **해결**: nginx에서 "없는 경로는 전부 index.html로 보내라"고 설정(SPA fallback). 그럼 React가 받아서 알아서 그림.


## 함정 2. 흰 화면(백지)만 뜸

빌드한 파일 경로가 안 맞으면 JS를 못 불러와서 화면이 하얗게 뜸.

- **해결**: 빌드 설정의 base 경로 확인. 브라우저 개발자도구(F12) Console에 빨간 에러(404 파일 못 찾음)가 있는지 봄. 보통 경로 문제임.


## 함정 3. WebSocket 연결이 끊김

채팅·알림 같은 실시간 기능을 쓰면, 라우팅 설정에 WebSocket 경로(`/ws` 등)를 안 열어둬서 연결이 안 됨.

- **해결**: nginx/Traefik에서 WebSocket 경로를 백엔드로 보내도록 열어줌. WebSocket은 일반 HTTP와 달리 연결 유지(upgrade) 설정이 필요함.


## 함정 4. 쿠키가 안 넘어감

프론트(`app.com`)와 백엔드(`api.app.com`) 주소가 다르면, 브라우저가 보안상 쿠키를 같이 안 보내거나 막음.

- **해결**: 백엔드 CORS 설정에서 해당 출처 허용 + 인증 정보 허용(credentials). 쿠키 대신 JWT를 `Authorization` 헤더로 보내면 이 문제를 많이 피함.


## 함정 5. API 경로가 프론트로 먹힘

함정 1 해결책(없는 경로 → index.html) 때문에, `/api/...` 요청까지 React 화면(index.html)으로 가버리는 경우가 있음. 그럼 API 호출했는데 HTML이 옴.

- **해결**: 라우팅에서 `/api`, `/ws` 같은 백엔드 경로를 먼저 백엔드로 보내고, 그 외만 index.html로 보냄(순서/우선순위 중요).


## 함정 6. CORS 에러

프론트와 백엔드 주소가 다르면 브라우저가 "다른 출처 요청"이라며 막음(CORS). Console에 빨간 CORS 에러가 뜸.

- **해결**: 백엔드에서 프론트 주소를 허용 출처로 등록. 개발 중엔 프록시 설정으로 우회하기도 함.


## 함정 7. 환경변수가 빌드에 안 박힘

React는 빌드 시점에 환경변수가 결과물에 박힘. 빌드 후에 값을 바꿔도 안 바뀜. 또 빌드 도구가 정한 접두사(Vite는 `VITE_`)가 없는 변수는 무시됨.

- **해결**: 변수 이름에 규칙 접두사 붙이기(`VITE_API_URL` 등), 값 바꾸면 다시 빌드.


## 정리

대부분 "SPA는 서버가 화면을 안 주고, JS가 화면을 그린다"는 한 가지 사실에서 파생되는 함정이었음. 라우팅(404·API·WebSocket), 출처 분리(쿠키·CORS), 빌드 시점(환경변수)만 기억해두면 대부분 예방됨.
