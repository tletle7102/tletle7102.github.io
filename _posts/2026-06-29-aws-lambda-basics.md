# AWS Lambda 정리

AWS Lambda가 "서버 없이 코드를 돌린다"는데 무슨 말인지 헷갈렸음. 서버가 진짜 없는 게 아니라 "내가 서버를 관리 안 한다"는 뜻이었음


## 1. 기존 방식: 서버를 내가 관리

평소엔 서버(EC2 등)를 빌려서 직접 관리함.

- 서버를 켜두고
- OS 업데이트, 용량 관리 하고
- 요청이 없어도 켜져 있으니 계속 돈이 나감

내 코드를 돌리려고 서버라는 "집"을 통째로 빌려서 관리하는 셈임.


## 2. Lambda: 함수만 올리면 알아서 실행

Lambda는 **함수(코드 한 덩어리)만 올려두면, 요청이 올 때만 알아서 실행해주는 서비스**임. 서버 관리는 AWS가 다 함. 그래서 "서버리스(serverless)"라고 부름. 서버가 없는 게 아니라, **내가 신경 안 써도 된다**는 뜻임.

```
요청 옴 → Lambda가 그 순간 내 함수를 실행 → 결과 줌 → 끝(꺼짐)
요청 없음 → 아무것도 안 돎(돈도 거의 안 나감)
```


## 3. 핵심 특징

- **요청当 실행**: 요청이 올 때만 잠깐 켜져서 함수를 돌리고 끝남.
- **쓴 만큼만 과금**: 실행한 횟수·시간만큼만 돈 냄. 놀고 있을 땐 거의 공짜.
- **자동 확장**: 요청이 갑자기 1000개 와도 알아서 1000개 동시에 돌려줌. 서버 늘릴 걱정 없음.
- **서버 관리 0**: OS, 용량, 패치 다 AWS가 함.


## 4. 어떨 때 쓰나

- 가끔만 실행되는 작업(이미지 썸네일 만들기, 알림 보내기 등).
- 트래픽이 들쭉날쭉한 기능(평소 한가하다 가끔 폭주).
- 간단한 API 한두 개.

반대로 항상 꽉 차게 돌아가는 큰 서비스는, 차라리 서버를 계속 켜두는 게 쌀 수도 있음. 그래서 무조건 Lambda가 답은 아님.


## 5. 한 가지 주의: 콜드 스타트

한동안 안 쓰다가 처음 호출되면, 함수를 띄우느라 살짝 느림(콜드 스타트). 자주 호출되면 따뜻하게 유지돼서 빨라짐.


## 6. 정리

- Lambda = 함수만 올리면 요청 올 때만 실행해주는 서버리스 서비스.
- 서버 관리는 AWS가 하고, 쓴 만큼만 과금, 자동 확장됨.
- 가끔·들쭉날쭉한 작업에 좋고, 항상 풀로 도는 서비스엔 안 맞을 수 있음.

> 보통 Lambda 혼자 안 쓰고, 다음 글의 API Gateway랑 같이 묶어서 "주소로 호출 가능한 API"를 만듦.
