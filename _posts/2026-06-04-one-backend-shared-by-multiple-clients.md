# 한 백엔드를 여러 클라이언트가 공유한다는 의미

"백엔드 하나로 웹도 앱도 다 된다"는 말을 처음 들었을 때 어떻게 가능한지 감이 안 왔음. 알고 보니 백엔드가 화면을 안 주고 데이터만 줘서 그런 거였음


## 1. 클라이언트가 뭔가

클라이언트(client)는 "백엔드한테 요청하는 쪽"을 다 합쳐 부르는 말임.

- 웹 브라우저 (React 화면)
- 아이폰 앱 (iOS)
- 안드로이드 앱

이 셋은 생긴 것도, 만드는 언어도 완전 다름. 근데 공통점이 하나 있음. **다들 "데이터"가 필요하다는 것.**


## 2. 백엔드가 화면이 아니라 데이터를 주면

만약 백엔드가 완성된 HTML 화면을 준다면, 그건 브라우저에서만 보임. 앱은 HTML을 그대로 못 씀.

근데 백엔드가 화면 대신 **데이터(JSON)** 만 주면 얘기가 달라짐. JSON은 그냥 글자라서 누구나 읽을 수 있음.

```
GET /api/users/1   요청에 대한 백엔드 응답:

{
  "id": 1,
  "name": "홍길동",
  "email": "hong@test.com"
}
```

이 JSON을 받아서

- 웹은 React로 화면을 그리고
- 아이폰은 Swift로 화면을 그리고
- 안드로이드는 Kotlin으로 화면을 그림

**데이터는 같고, 화면 그리는 방법만 각자 다른 것**임.


## 3. 그래서 "공유"가 된다

```
[웹(React)]    ─┐
[iOS 앱]       ─┼──> [백엔드 하나]  (같은 /api/... 호출)
[안드로이드 앱] ─┘
```

세 클라이언트가 똑같은 주소(예: `GET /api/users/1`)를 호출함. 백엔드는 누가 부르든 똑같은 JSON을 줌. 그래서 백엔드 하나를 셋이 같이 쓸 수 있는 거임.

식당으로 치면, 주방(백엔드)은 똑같은 음식을 만들고 그걸 매장 손님, 배달, 포장(웹/iOS/안드로이드)이 각자 가져가는 느낌임.


## 4. 정리

- 백엔드가 화면이 아니라 데이터(JSON)를 주는 게 핵심임.
- JSON은 누구나 읽을 수 있어서 클라이언트 종류를 안 가림.
- 그래서 백엔드 하나로 웹/앱 여러 개를 동시에 지원할 수 있음.

> 이렇게 "데이터만 주는 백엔드"를 보통 REST API 서버라고 부름. 화면은 각 클라이언트가 알아서 만드는 게 핵심 원리임.
