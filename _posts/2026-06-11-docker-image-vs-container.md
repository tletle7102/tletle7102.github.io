# Docker 이미지 vs 컨테이너

도커 배우면서 "이미지"랑 "컨테이너"라는 말이 둘 다 나오는데 뭐가 다른지 한참 헷갈렸음. 내가 잡은 멘탈모델을 정리함


## 1. 한 줄 비유: 붕어빵 틀 vs 붕어빵

- **이미지(image)** = 붕어빵 **틀**. 만드는 설계도이자 본보기.
- **컨테이너(container)** = 그 틀로 찍어낸 **붕어빵**. 실제로 돌아가는 것.

틀(이미지) 하나로 붕어빵(컨테이너)을 여러 개 찍어낼 수 있음. 이게 핵심임.

```
이미지 1개  →  컨테이너 여러 개 (똑같이 찍어냄)
```


## 2. 이미지 = 결과물이 박혀서 굳은 것

이미지는 **빌드된 결과물 + 실행 환경이 통째로 박혀서 굳어버린 덩어리**임.

예를 들어 React 이미지를 만들면, 그 안에는 이미 이런 게 다 들어가 굳어 있음.

- nginx
- 빌드된 `dist` 파일들

한 번 이미지로 만들면 내용이 안 바뀜(읽기 전용). 그래서 어디서 실행하든 똑같음. 내 노트북에서 만든 이미지를 서버에 가져가도 똑같이 돌아감.

> "이미지 안에 빌드 결과물이 박힌다"는 게 핵심 멘탈모델임. 코드가 따로 떠다니는 게 아니라, 빌드 시점에 이미지 안으로 들어가 굳음.


## 3. 컨테이너 = 이미지를 실제로 돌린 것

이미지는 굳어 있는 틀일 뿐, 그 자체로 돌아가진 않음. 이미지를 **실행하면** 그게 컨테이너임.

```
docker run my-image   →  컨테이너 시작 (실제로 nginx가 돌기 시작)
```

- 이미지: 디스크에 가만히 있는 설계도
- 컨테이너: 그 설계도로 실제로 살아 움직이는 프로세스

붕어빵 틀은 가만히 있고, 붕어빵은 실제로 먹을 수 있는 물건인 것처럼.


## 4. 왜 이렇게 나누는가

- **재현성**: 이미지에 다 박혀 있으니 어디서 실행해도 똑같음. "내 컴퓨터에선 됐는데요"가 사라짐.
- **확장**: 같은 이미지로 컨테이너를 여러 개 띄워서 트래픽을 나눠 받을 수 있음.
- **격리**: 컨테이너는 각자 독립된 공간에서 돎. 하나 죽어도 다른 거랑 안 섞임.


## 5. 정리

| 구분 | 이미지 | 컨테이너 |
|---|---|---|
| 비유 | 붕어빵 틀 | 찍어낸 붕어빵 |
| 상태 | 굳어 있음(읽기 전용) | 실제로 돌아감 |
| 개수 | 1개 | 그 이미지로 여러 개 |

- 이미지 = 빌드 결과물이 박혀 굳은 설계도.
- 컨테이너 = 그 이미지를 실행해 살아 움직이는 것.
- `docker build`로 이미지를 만들고, `docker run`으로 컨테이너를 띄움.
