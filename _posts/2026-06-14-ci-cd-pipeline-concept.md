# CI/CD 파이프라인이란

CI/CD라는 말을 자주 듣는데 정확히 뭔지 몰랐음. 알고 보니 "코드 올리면 알아서 테스트하고 배포까지 해주는 자동화"였음. 개념을 정리함


## 1. 자동화 전엔 어땠나

옛날 방식으로 배포하면 이런 걸 사람이 손으로 다 했음.

```
코드 다 짬
 → 직접 빌드함
 → 직접 테스트 돌림
 → 서버에 직접 접속해서 파일 올림
 → 직접 서버 재시작함
```

귀찮고, 실수하기 쉽고, 하는 사람마다 방식이 달라서 사고가 남. ("저는 테스트 깜빡했어요" 같은 거)


## 2. CI = 코드를 합치고 검증하는 자동화

CI(Continuous Integration, 지속적 통합)는 **코드를 올릴 때마다 자동으로 빌드하고 테스트하는 것**임.

```
git push
 → (자동) 빌드 됨
 → (자동) 테스트 돌아감
 → 통과하면 OK, 깨지면 바로 알려줌
```

핵심은 "문제를 빨리 발견"하는 거임. 코드를 합칠 때마다 자동으로 검사하니까, 깨진 코드가 쌓이기 전에 잡힘.


## 3. CD = 배포까지 자동화

CD는 두 가지 뜻으로 쓰는데 입문 단계에선 비슷하게 봐도 됨.

- Continuous Delivery(지속적 전달): 배포 직전까지 자동. 마지막 배포 버튼만 사람이 누름.
- Continuous Deployment(지속적 배포): 배포 버튼도 자동. 통과하면 알아서 실서버까지 나감.

```
테스트 통과
 → (자동) 이미지 빌드
 → (자동) 서버에 배포
 → (자동) 새 버전으로 교체
```


## 4. 파이프라인이란

이 단계들(빌드 → 테스트 → 배포)을 쭉 이어놓은 자동 흐름을 **파이프라인(pipeline)** 이라고 부름. 공장 컨베이어 벨트처럼, 코드가 한쪽에서 들어가면 단계를 거쳐 반대쪽에서 "배포 완료"로 나옴.

```
[git push] → [빌드] → [테스트] → [배포] → [완료]
            └─────── 이 흐름 전체가 파이프라인 ───────┘
```


## 5. 그래서 왜 쓰는가

- **실수 감소**: 사람이 손으로 안 하니까 빠뜨리는 게 없음.
- **속도**: push 한 번이면 배포까지 자동으로 감.
- **일관성**: 누가 하든 똑같은 단계를 거침.


## 6. 정리

- CI = 코드 올릴 때마다 자동 빌드·테스트 (문제를 빨리 발견).
- CD = 그 다음 배포까지 자동.
- 파이프라인 = 이 단계들을 이어놓은 자동 흐름.
