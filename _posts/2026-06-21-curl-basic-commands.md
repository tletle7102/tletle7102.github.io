# curl 기본 명령어

배포하고 나서 "잘 떴나" 확인할 때 브라우저 말고 curl을 쓰면 빠르다고 함. 자주 쓰는 옵션 위주로 정리함


## 1. curl이 뭔가

curl은 **터미널에서 주소로 요청을 날려보는 도구**임. 브라우저가 하는 일(요청 보내고 응답 받기)을 명령어로 하는 거임. 배포 검증이나 API 테스트할 때 많이 씀.

```
curl https://example.com
```

이러면 그 주소의 응답 내용(HTML 등)이 터미널에 쭉 나옴.


## 2. -I : 본문 말고 헤더만 보기

`-I`(대문자 아이)를 붙이면 **응답 본문은 빼고 헤더만** 보여줌. 헤더에는 상태 코드, 서버 종류, 리다이렉트 정보 같은 핵심만 들어 있음.

```
curl -I https://example.com
```

결과 예시:

```
HTTP/2 200
server: nginx
content-type: text/html
```

맨 위 `200`이 핵심임. "정상 응답"이라는 뜻. 화면 내용 전부 받을 필요 없이, **"잘 떴는지"만 빠르게 확인**할 때 딱임.


## 3. 상태 코드로 라우팅 검증하기

배포 후에 "이 경로가 제대로 연결됐나"를 확인할 때 상태 코드를 봄.

- `200` : 정상.
- `301`/`302` : 다른 데로 리다이렉트됨.
- `404` : 경로를 못 찾음(라우팅 잘못됐을 가능성).
- `502`/`503` : 뒤쪽 서버가 죽었거나 아직 안 떴음.

예를 들어 백엔드 API를 확인하려는데 프론트의 빈 화면(200)이 와버리면, 라우팅이 백엔드가 아니라 프론트로 잘못 가고 있다는 뜻임. 이런 걸 `-I`로 빠르게 잡음.


## 4. 자주 같이 쓰는 옵션

```
curl -fsS -o /dev/null https://example.com
```

- `-f` : 실패(400/500 등)면 에러로 처리. 스크립트에서 유용.
- `-s` : 진행 막대 같은 불필요한 출력 숨김(silent).
- `-S` : 그래도 에러 메시지는 보여줌.
- `-o /dev/null` : 응답 본문은 버림(상태만 보고 싶을 때).

이 조합은 Healthcheck에서도 많이 쓰임.


## 5. 정리

- curl = 터미널에서 주소로 요청 날려보는 도구.
- `-I` = 헤더만 보기. 상태 코드로 "잘 떴는지" 빠르게 확인.
- 상태 코드(200/404/502 등)로 라우팅이 제대로 됐는지 검증함.

> 배포하고 브라우저 새로고침 누르기 전에, `curl -I 주소` 한 줄이면 정상 여부를 더 빠르게 알 수 있음.
